Local SQLite capability:
  The privileged default remains fixed at /usr/bin/python3; there is no runtime override.
  backupPythonRuntime.ts probes only in-memory SQLite using isolated Python subprocesses.
  A supported runtime requires Python>=3.8, SQLite>=3.31, and BOTH setting/querying
  PRAGMA hard_heap_limit yielding a positive value <=67108864.
  On this Mac the already installed /opt/homebrew/bin/python3.13 is compatible:
    Python3.13.15 / SQLite3.53.4 / heap limit67108864.
  The fixed Apple/Xcode interpreter's zero limit is classified UNSUPPORTED.
  The Homebrew alternative is test-only and only considered on nonroot macOS; Linux/root
  checks always use the fixed OS interpreter. Nothing is downloaded or PATH-discovered
  dynamically during tests.
  SQL reference tests are explicitly capability-gated. The producer guard is checked
  OUTSIDE expected-failure handling, so a failed heap prerequisite cannot fake a passing
  malformed-reference assertion. Pure basename/descriptor tests need no SQLite limit.
  Affinity-free fixtures bind integral sizes as bigint: better-sqlite3 JS numbers otherwise
  become REAL, causing a false "valid" fixture to fail strict INTEGER validation.

PORTABLE STDLIB-ONLY LINUX/ROOT DRIVER
  File: backup_linux_runner.py (beside this document).
  No Node/native Node binding, npm, new framework, container daemon, downloads or network.
  It runs31 fixed cases against the reviewed producer and actual backup.sh using exclusively
  generated fixture databases/evidence. A separate bounded Python writer keeps committed
  WAL transactions open; no live SQLite connection crosses the producer's fork.
  A valid synthetic root-only SQLite sentinel and WAL are used for path-race tests.
  Injected DB/WAL swaps are restored before post-checks, ensuring that post-check rejection
  alone cannot masquerade as successful confinement.
  Coverage includes WAL, absent evidence schema, 2/3 arguments + DB_FILE, DB/sidecar/evidence
  symlinks, traversal/control/NUL/length/count limits, directory swaps, hardlinks/FIFO,
  missing/changed evidence, leaked VFS directory capability, inherited FD closure,
  root-owned source rejection, exclusive existing outputs, and restored-copy integrity.

  The driver refuses the real application/data/backup roots and /tmp or /var/tmp.
  It requires an empty dedicated root-owned0700 project with EXACTLY this layout:
    .isolated-backup-fixture-project
    scripts/backup.sh
    scripts/backup_producer.py
    tests/backup_linux_runner.py
  Marker bytes must be exactly: SYNTHETIC BACKUP FIXTURES ONLY followed by LF.
  All files/ancestors must be root-controlled, nonsymlinked and not group/world writable.
  Use ONLY authenticated reviewed build-artifact code, never code copied from a live app.
  Staged producer scripts must match payload/scripts/ from the authenticated v5 archive;
  do not substitute an older release or confuse anchor-v3 with release-name versions.
  The existing local UID/GID65534 must be available; the runner creates no OS/app users.
